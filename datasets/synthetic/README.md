# Synthetic datasets

Every organisation, person, price and certificate in this directory is **fictional** and exists
only to exercise the pipeline against real file formats. Nothing here is derived from a customer
document.

Two splits are shipped:

| Split | Files | Documents (unique `doc_key`) | Versions | Decisions | Purpose |
| --- | --- | --- | --- | --- | --- |
| `dev/` | 25 | 24 | 25 | 7 | Development workspace, also what the seeded demo uses |
| `heldout/` | 21 | 20 | 21 | 6 | Independent check never used while tuning extraction |

The file count exceeds the document count by one in each split: a revised quotation (`apex_quote_v1`
→ `apex_quote_v2`, `helios_quote_v1` → `helios_quote_v2`) is ingested as a second immutable version
of the same `doc_key`.

Both are generated by `build.py` and committed, so a clone is enough to reproduce every result.
Regenerate with:

```bash
PYTHONPATH=backend .venv/bin/python datasets/synthetic/build.py
```

Regeneration writes the same bytes as long as `build.py` is unchanged; the document hashes are
therefore stable, but the ground-truth labels in `evaluation/ground_truth/` are hand-authored
**against the specification in this README and `build.py`'s scenario table**, so if you change
wording or numbers you must update the labels deliberately.

## Scenarios

### dev

| # | Decision | Type | What the documents test |
| --- | --- | --- | --- |
| 1 | Approve Apex Systems as compressor supplier — Chennai Phase 2 | procurement | Price/delivery/payment-term conflict between quotation revision 2 and the signed contract; superseded revision 1; expiring ISO certificate |
| 2 | Borealis Industrial spare-parts supply award | procurement | Obsolete certificate, missing contract coverage, quotation only — incomplete evidence |
| 3 | Chennai Phase 2 — milestone M2 release | project_approval | Missing risk register, schedule vs. status date conflict |
| 4 | Award pump maintenance contract to Cascade Pumps | procurement | Clean, complete supplier file — should reach `APPROVED` after attestation |
| 5 | Engineering change EC-2025-14 — compressor control upgrade | engineering_change | Change assessment, risk register, spec and a dependency on case 1 |
| 6 | Travel and Expense policy compliance review — Q3 2025 | policy_compliance | Policy text, attestation email and review record; no numeric claims needed |
| 7 | Vendor bank-detail change review (draft) | procurement | Deliberately empty draft; shows the `DRAFT` state and an unevaluated gate |

The `apex-quote` pair is the supersession case: `apex_quote_v1.pdf` (245,000) is replaced by
`apex_quote_v2.pdf` (252,000). The old figures must remain queryable as history but never count as
current evidence.

`vendor_note_injection.txt` contains instruction-like text ("ignore previous instructions…") and
is used to prove injection containment: it is flagged at ingest, contributes zero claims, and must
not influence the Apex decision.

### held-out

Different vendors and values with the same structural challenges, plus a second obsolete-record
case:

- Helios Valves supplier selection — North Grid (blocking certification conflict)
- Kestrel Fabrication valve supply award
- Solstice Pumps valve supply award
- North Grid milestone M2 release (missing requirement)
- Asset register policy compliance review — H1 2025
- Control retrofit HC-14 engineering change

There is no injection document in the held-out split; `injection_containment` is reported as `n/a`
there rather than silently scoring 1.0.

## File map

| File | Format | Provenance captured |
| --- | --- | --- |
| `*_quote*.pdf`, `*_contract.pdf`, `*_certificate.pdf` | PDF (text layer, ReportLab) | page number + bounding box of the line containing the claim |
| `borealis_quote.docx`, `*_spec.docx` | DOCX | paragraph index + full paragraph text |
| `project_*.xlsx`, `change_risk_register.csv`, `risk_register.csv` | XLSX / CSV | sheet name + cell range |
| `*.md`, `*.txt`, `vendor_note_injection.txt` | Markdown / plain text | character offset + line |
| `project_status.json` | JSON | JSON pointer path + character offset |
| `policy_attestation.eml` | EML | `Message-ID` + section (body/attachment) |

`manifest.json` in each split is the ingestion plan: workspace, demo users, documents (with
`doc_key` and `effective_date`/`valid_until`), and decisions (type, options, linked documents,
`as_of_date`, and the actions to run).

## Loading a split

```bash
# the demo workspace (dev split, with the seeded decisions evaluated)
PYTHONPATH=backend .venv/bin/python -c "from app.seed import seed_demo; seed_demo(force=True)"

# or ingest the files yourself through the API
for f in datasets/synthetic/dev/files/*; do
  curl -s -X POST http://localhost:8000/api/documents/upload \
    -H "Authorization: Bearer $TOKEN" \
    -F "file=@$f" -F "doc_type=quote" >/dev/null
done
```

## Adding a scenario

1. Add the document text and metadata to the scenario table in `build.py`; keep numbers explicit
   and dates ISO-formatted.
2. Run `build.py`, then ingest and inspect the claims the extractor produces.
3. Write the labels **by hand** in `evaluation/ground_truth/` (never copy application output) and
   add the decision's expected gate status.
4. Re-run `scripts/run_benchmark.py --dataset all` and update `docs/benchmarks.md`.

Keep plain-text corpora out of the default seed: the demo needs to fit in a SQLite file that is
easy to reset.
