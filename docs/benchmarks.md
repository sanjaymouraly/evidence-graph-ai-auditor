# Benchmark methodology and results

This document describes how the numbers in the [README](../README.md#benchmark-results) are
produced, what they do and do not measure, and where the pipeline fails.

Reproduce:

```bash
PYTHONPATH=backend .venv/bin/python scripts/run_benchmark.py --dataset all
# results: evaluation/benchmarks/{dev,heldout}-<UTC>.json and latest-{dev,heldout}.json
```

Each run runs in a **throwaway SQLite database** created under `evaluation/benchmarks/.scratch`,
seeded only from the chosen split. The application database is never touched.

## 1. Corpora

Both splits are generated by `datasets/synthetic/build.py` and committed with their labels, so a
result is reproducible from the repository alone.

| | dev | held-out |
| --- | --- | --- |
| Documents | 24 | 20 |
| Versions | 25 | 21 |
| Claims (produced) | 111 | 96 |
| Labelled claim links | 45 | 51 |
| Contradiction pairs | 4 | 4 |
| Non-contradiction pairs (must stay unflagged) | 3 | 4 |
| Supersession cases | 1 | 1 |
| Obsolete-record cases | 1 | 2 |
| Missing-requirement cases | 1 | 1 |
| Decisions | 7 | 6 |
| Citation spot checks | 6 | 6 |
| Injection case | yes | none |

Held-out documents use different vendors, entity names, values and sentence shapes. They were
**not** used while tuning extraction rules; only the dev split was.

### Labelling

`evaluation/ground_truth/{dev,heldout}.json` is authored from the scenario specification, not
from application output. Each claim label records the document key, predicate, subject, normalised
value and the locator the claim must resolve to. Contradiction labels include the pair of claims,
their kind and whether they must be blocking. The four required targets are the union of
`README` claims and this file; nothing in the scoring path reads ground truth before scoring, and
no filename, document key or id is special-cased in the application code.

### Defences against overfitting

- **Separate authorship path**: labels are written against the scenario spec, not copied from
  extraction output.
- **Held-out split**: identical code, different content; the numbers are reported separately.
- **Property/metamorphic tests** (`backend/tests/`): normalisation round-trips, unit and currency
  equivalence, idempotent re-ingestion, supersession ordering, and the invariant that a recorded
  exception never changes a gate result or hash.
- **Negative pairs**: contradiction detection is also scored on pairs that must *not* be flagged
  (`non_contradiction_pairs`, e.g. different scopes or periods), so recall cannot be bought with
  aggressive matching.
- **Deterministic re-runs**: two consecutive runs on the same split produce identical metrics;
  the harness is pure with respect to the corpus.

## 2. Metrics

| Metric | Definition |
| --- | --- |
| `claim_precision` / `claim_recall` / `claim_f1` | Labelled claims matched vs. produced in scope |
| `claim_link_precision` | Share of produced claim links whose document, predicate, subject, value **and locator** all match a label |
| `citation_validity` | Share of claims whose quoted span resolves exactly against the stored span text |
| `contradiction_precision` / `recall` / `f1` | Confirmed contradictory pairs vs. labelled pairs |
| `contradiction_blocking_accuracy` | Labelled pairs whose blocking severity matches |
| `gate_accuracy` | Decision gate status equals the labelled expected status |
| `final_status_accuracy` | Workflow status (including `APPROVED`) equals the labelled expectation |
| `blocking_check_recall` | For blocked decisions, the specific failing check is the labelled one |
| `freshness_detection_accuracy` | Decisions blocked for expiry are the labelled ones |
| `missing_document_accuracy` | Missing mandatory source types match the label |
| `supersession_accuracy` | Latest version wins and a `SUPERSEDES` edge exists |
| `retrieval_recall_at_5` | Labelled relevant document keys present in the top 5 for the decision query |
| `retrieval_mrr` | Mean reciprocal rank of the first relevant document |
| `injection_containment` | Injection document flagged, and zero unflagged claims extracted from it |
| `unsupported_conclusion_rate` | Share of analysis statements that fail citation validation |

Confusion matrices (gate status expected × actual) are stored per run and rendered in the
**Benchmarks** screen.

embedder reliably ranks the single best source first (MRR 1.0) but misses secondary supporting
documents that use different vocabulary.

## 4. Error analysis

The pipeline makes no errors on either split, so this section records the *near misses and
structural weaknesses* found while building it, rather than cherry-picked successes.

1. **Secondary-source retrieval gaps (measured).** Apex retrieval scored recall@5 = 0.6: the
   top hit was correct, but `apex-certificate` and `borealis-quote` were not in the top 5 because
   their vocabulary barely overlaps the decision text. A model-backed embedding provider fixes
   this class of miss; the deterministic hashing embedder does not.
2. **Decision-date vs. verification-date semantics (fixed).** Claim verification runs at "now",
   so quotations expired *today* were labelled `unsupported`. Option comparison then dropped
   evidence that was valid on the decision's as-of date, producing a comparison with missing
   values next to a gate that correctly used those claims. Fixed by scoring comparisons against
   `as_of` with an explicit staleness check; regression tests in
   `backend/tests/test_mcda_dates.py`.
3. **Attestation invalidation on re-analysis (fixed).** Regenerating an already-approved analysis
   changed the pre-attestation hash and silently demoted `APPROVED` to `REVIEW_REQUIRED`, even
   though the evidence had not changed. The hash now binds the deterministic checks only; the
   advisory AI-grounding check is excluded, and any real demotion emits
   `decision.approval_invalidated`.
4. **Unstable evidence ordering (fixed).** Claims with equal facts from different sources could
   be returned in different database orders, so re-running analysis cited a different subset.
   Deterministic total ordering by (subject, predicate, value, effective date, id) now makes the
   generated statements byte-identical across runs.
5. **Extraction boundary.** Scanned PDFs produce no claims (no OCR). Documents whose numbers are
   written as words or in unusual formats (`USD 1.2M`, `1 200 000`) are parsed only if the
   normaliser recognises the pattern; unparsed values become `unsupported` rather than silently
   wrong.
6. **Contradiction boundary.** Rules compare normalised values under compatible scope, period and
   currency. They catch price, delivery, payment-terms, warranty and polarity conflicts. They do
   not catch contradictions that require domain reasoning ("ISO 9001 expires 2025-03-31" vs. a
   later claim that certification "remains valid"), which is why the gate also checks freshness
   independently.
7. **Single-region synthetic data.** All documents are English, metric/`USD`, and structurally
   simple (single-column PDFs, one-sheet spreadsheets). Table-merge cells, footnotes and
   multi-currency contracts are untested.

## 5. What is *not* measured

- Live paid LLM behaviour (no paid credentials in this environment). The validator is unit-tested
  against adversarial statements, the offline baseline is what the benchmark scores, and a local
  Ollama (`gemma:2b`) path was exercised separately in the UI/API but not included in these offline
  benchmark numbers.
- OCR quality, since OCR is not implemented.
- Human review time, inter-annotator agreement, or label error rates.
- Load behaviour under concurrent ingestion.

## 6. Reproducing a specific historical result

```bash
# every artefact carries corpus stats, environment, per-case detail and confusion matrices
python - <<'PY'
import json, glob
for f in sorted(glob.glob("evaluation/benchmarks/2*.json")):
    d = json.load(open(f))
    print(f, d["dataset"], round(d["duration_seconds"], 2), d["environment"])
PY
```

The dashboard reads the same payload from `benchmark_runs.payload` for runs triggered through the
API, so a UI number can always be traced to a stored run.
